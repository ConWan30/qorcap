# Sight-to-shot Stage S1: `qorcap s2s-counted`

Offline and read-only. It reads one bundle's `inputs.jsonl` (plus `bundle.json` `match_id` for the bundle's own id) and writes one JSON report to `--out`, which must be **outside every bundle folder** (seal integrity). No video, frame clock, screen reader or detector is read. Plan: sight-to-shot PLAN-r9 (sha256 `b3e3c603…8caa`) with amendments r10 (sha256 `1104de94…f684`) and r11 (sha256 `d7bf545a…663e`).

> **COUNTED is disabled in this build.** `COUNTED_ENABLED = false` in `src/s2s.rs`. No CLI flag or config value can produce COUNTED: every output is `INFO_ONLY` (or `DESCRIPTIVE_ONLY_HOLDOUT_REUSED`, or `NOT_COUNTED_CALIBRATION_SET`), and every report carries `counted.enabled: false` and the reason `counted_disabled_in_this_build`. `--seal-status` and the config `"status"` (even a hand-edited `"frozen"`) are recorded as caller claims only (`seal_status_claim`, `status_claim`, both with `..._checked: false`). COUNTED needs a later PR in which the tool itself recomputes the seal and the input hash chain and checks `threshold_id` (which includes the freeze status) against the ledger.

```
qorcap s2s-counted <bundle-or-inputs.jsonl> --out <report.json> [--session-id <id>] \
    [--config docs/s2s/threshold_A.standby.json] [--seal-status rehashed_match|locked_not_rehashed|failed|missing] \
    [--disposition ok|UNKNOWN|VOID|FAIL] [--in-calibration-set] [--holdout-reused]
```

**Bundle identity (exclusions are bound to the bundle).** The session id is read from the bundle: the folder must be named `match-<stamp>` and `bundle.json` `match_id` must be `local-<stamp>` with the same stamp. A missing or unreadable `bundle.json`, a folder with another name, or a stamp mismatch (a renamed or copied folder) is refused (exit 2). `--session-id` is optional; if given it must name that same id (`match-<stamp>`, `local-<stamp>`, `<stamp>` or its time part, e.g. `073204`), or the run is refused. Exclusions match the bundle's id, and also `inputs_sha256` when a list entry carries one (none of the listed sessions has a known hash here: UNKNOWN). `--seal-status` and `--disposition` accept only the listed values (any case).

**Output path.** Refused when it is inside the input's bundle folder, or inside **any** folder (at any level above it) that holds a bundle marker file (`inputs.jsonl`, `manifest.jsonl`, `bundle.json`, `receipt.json`, `receipt.v0.json`, `receipt.draft.json`, `checkpoints.jsonl`), or when `--out` already exists as a symlink, a hard-linked file (link count > 1, checked on Unix) or a non-file. The report is written to a temp file in the target folder and then renamed over `--out`, so an existing link is replaced, never written through. A bare relative `inputs.jsonl` (no folder in the path) has an empty bundle path and **every write is refused** (fail-safe); pass the bundle folder instead. The config is validated first (`release_d < onset_d <= 127`, `0 < quiet_us < window_us`, `1 <= edge_delta <= 254`, `burst_gap_us > 0`, `min_bursts_for_headline >= 1`, rule `ii`).

**What COUNTED would mean (once a later build enables it).** Host-observed USB rows that passed the preregistered gates on this capture setup. It is a private descriptive tier only: not a rating, not a measure of the person, not checked by a referee, never gold. It does not show who held the controller or that the input came from a person. The physical thumb onset is UNMEASURED.

## Rule (inputs.jsonl rows only)
- **S4 anchor.** R2 edge = an R2 analog jump of more than `edge_delta` (60) between consecutive `in` rows, exactly `trigger_edges()` in `sidecar/qorcap_cod.py`. A slow squeeze makes no edge. The R2 digital bit is recorded as a diagnostic (`t_us_bit_diagnostic`) and never makes an edge. Edges `<= burst_gap_us` apart merge into one burst; the burst's first edge is the anchor.
- **Window.** S1-blind `[R2 - W, R2]`. Nothing screen-side is read, so no S1 value can move the selection (fixture: `s1_perturbation_invariance`).
- **S2, onset rule (ii).** Deflection `d = max(|rx-128|, |ry-128|)` clipped 127. An onset is the first `in` row with `d >= onset_d` after a span of at least `quiet_us` with `d <= release_d` throughout, inside the window (hysteresis: after an onset the stick must fall to `<= release_d` before another). Every qualifying onset is kept in `s2_candidates[]`; more than one sets `multi_onset`; the first is selected.
- **Throttle.** `in` rows are change-only and analog-only changes are logged at most every 4 ms (`ANALOG_MIN_GAP_US`, `src/inputs.rs:56`, applied at `:484-485`; re-read at main `4888a63`). S2 is the logged row time; `prev_row_gap_us` and `t_us_bracket = [previous in row, onset row]` carry the uncertainty.
- **Outcome per anchor (exactly one).** `onset`, `no_onset`, `left_censored_stick` (stick deflected at window start and no qualifying onset), `onset_reused` (the selected onset already went to an earlier anchor; not counted twice), or `masked:<reason>`.
- **Span gates.** Span = `[baseline start, R2]` for an onset, `[R2 - W, R2]` otherwise. Masks: `transport_not_usb` (header or any row in the span not `usb-hid`), `transport_unknown` (no header transport), `controller_status_change_in_window`, `no_hb`, `epoch_change_in_window`, `hb_gap_in_window` (non-contiguous `hb_seq`, faults, short reads, parse faults, `stale_over_50ms`, `max_rx_gap_us > 50,000`), `report_seq_break`, `window_before_first_row`. hb rows without `seq_breaks` (older builds) pass with flag `seq_breaks_unrecorded`.

## Tiers and the headline
- `COUNTED`: **unreachable in this build** (see the box above).
- `INFO_ONLY` for every normal run, with `info_only_reasons` (always `counted_disabled_in_this_build`, plus `stick_onset_threshold_provisional`, `seal_not_rehashed`, `seal_failed`, `seal_missing` as they apply). The headline is `NOT_COUNTED`; values appear only under `descriptive` with `not_counted: true`.
- `DESCRIPTIVE_ONLY_HOLDOUT_REUSED` (`--holdout-reused`, PLAN-r10 R10-3): never COUNTED, excluded from the headline and every COUNTED table.
- `--in-calibration-set`: tier `NOT_COUNTED_CALIBRATION_SET`; no per-burst rows and no timing values (R1); only the threshold-free gate-passing burst count (M4).
- Excluded sessions (built in, `builtin_exclusions()` in `src/s2s.rs`: 073204 EXCLUDED per PLAN-r11 R11-3, agent-relayed and QorProof-unverified; 201029 and 153536 VOID; 112342 FAIL) and `--disposition VOID|FAIL` (any case): `status: excluded`, nothing else. Exclusions are **add-only**: the effective list is the built-in list plus the config's `excluded_sessions`, so an empty or missing config list removes nothing (QorProof r2 R-M1b).
- **Headline (descriptive, never COUNTED here):** label "R2 press bursts". The S2 -> S4 distribution (`n`, `median_us`, `p25_us`, `p75_us`, `iqr_us`, `min_us`, `max_us`) over every gate-passing burst with outcome `onset`, always next to the full `outcome_table`. Fewer than `min_bursts_for_headline` (30) -> `status: UNMEASURED`, no value. No screen-side filter (post-death, killcam, HUD) touches it.

## Report fields
`schema` `qorcap-s2s-counted/v0`; `session{session_id (the bundle's own id), session_id_source, session_id_typed, inputs_sha256, seal_status_claim, seal_status_checked: false, disposition_claim, in_calibration_set, holdout_reused}`; `threshold{threshold_id, provenance{source, status_claim, status_checked: false, ...}, params, code_pins}`; `counted{enabled: false, note}`; `counts`; `tier`; `info_only_reasons`; `outcome_table{outcomes, multi_onset, gate_passing_r2_bursts, r2_bursts}`; `headline` (always `NOT_COUNTED` here); `descriptive`; `anchors[]` with `anchor_id = sha256([session_id, epoch, r2_edge_t_us, edge_rule_id])`, `epoch`, `tier`, `outcome`, `flags`, `s4_r2`, `burst`, `window_us`, `s2_candidates[]{onset_id = sha256([session_id, epoch, onset_t_us, threshold_id]), t_us, axis, d, prev_row_gap_us, t_us_bracket, baseline_start_us, quiet_us}`, `s2_selected`, `s2_s4_us`, `hb_span`, `threshold_id`, `threshold_provenance` (on every row); `gold: false`, `referee_submit: false`, `upload: false`. The report is not in the bundle, the hash chain, `receipt.v0` or `contracts/`.

## threshold_id
`sha256(JCS({schema, source, status, params, tuning_sessions[{session_id, seal_status, inputs_sha256}], heldout_sessions, code_pins{main_sha, refs, drift}, excluded_sessions (the effective add-only list)}))`. The freeze status **is** part of it (a hand-edited `"frozen"` changes the id, so it cannot match a ledgered one), and so is the effective exclusion list (adding an exclusion changes the id; emptying the config list does not, because the built-ins stay). `docs/s2s/threshold_A.standby.json` is the standby (A) rule (`status: standby_unfrozen`); a test keeps it identical to `Config::standby_a()`, and another fails if any pinned code line drifts. Freezing a real threshold, the ledger entries, seal re-hash checks and any run on real sessions are outside this tool and still gated (PLAN R7-3).

## Related change in the same PR: `alignment` in `input_proof.json` (align 60 fps fix)
Not part of this tool, recorded here because it changes an output shape inside `qorcap-input-proof/v0` (QorProof M3):
- `alignment.fps` was always the integer `30`. It is now the session's own rate rounded (`30`, `60`, ...), or **`null`** when no video was decoded (no ffmpeg, no segments, every rate UNMEASURED) or when the decoded parts have mixed rates. Old readers that expect an integer must accept `null`.
- `alignment.fps_status` (new, optional): `"UNMEASURED: ..."`, present only on the mixed-rate fail-closed path.
- `alignment.parts_unscored_unknown_rate` (new, optional): `{count, of_parts, files[]}`, present only when some video parts were left out because their rate is UNMEASURED (the rest are scored).
- Notes may include `avg_frame_rate ... differs from r_frame_rate ...` (note only; scoring uses `r_frame_rate`). Written only when the two differ by more than 1/2000 (0.05%, `align::AVG_RATE_NOTE_TOLERANCE`): an NTSC 30000/1001 or 60000/1001 stream labelled 30/1 or 60/1 (0.0999%) is still noted; duration-rounding drift on a genuine 30/1 or 60/1 file (for example 59.99x) is not.
- No consumer found reads `alignment.fps` (qortime `qor_receipt/receipt.py` `_input_proof_advisory`, `review/bundle.py`, `match_index/build.py`, qorcap `inputproof::receipt_fields`). `receipt.v0` fields and shape are unchanged; `signals.input` values change for 60 fps recordings (corrected).

## Known residuals (QorProof r2), acceptable only while every output is INFO_ONLY
- **R-M1a: a re-stamped copy is not excluded.** A copy of a listed bundle whose folder name *and* `bundle.json` `match_id` are both changed to a new consistent stamp passes the id check and runs (INFO_ONLY). The content key `inputs_sha256` would catch it, but it is `None` (UNKNOWN) for every built-in entry: filling it needs read-only hashes of the real session files, which this tool and its tests do not read. The test `restamped_copy_is_a_known_residual_while_info_only` pins the current behaviour and shows a filled hash excludes the copy. Must be closed (hashes filled from the real files, under the PLAN gate) before COUNTED can ever be enabled.
- **Output hard links on Windows** are now refused the same way as on Unix (`nNumberOfLinks` from `GetFileInformationByHandle`; a file whose link count cannot be read is refused). The temp-file-plus-rename write remains the guard against writing through any link.
- TOCTOU between `check_out` and the rename (LOW, needs a racing local writer) is unchanged.
